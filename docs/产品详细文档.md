## 一、项目背景

### 1.1 产品定位

"记工算工钱"是一款面向建筑工人、工厂普工、临时工等蓝领群体的记工记账工具。核心解决三个痛点：

1. **记工混乱** — 工人常用纸笔或记忆记录工时，容易遗漏、算错
2. **算钱麻烦** — 平日/周末/节假日费率不同，手工计算容易出错
3. **对账困难** — 发工资时无法快速核对预估与实发金额

### 1.2 目标用户

| 用户类型 | 特征 | 核心场景 |
|----------|------|----------|
| 建筑工人 | 按日/按件计薪，多工地切换 | 每天打卡记工，月底对账 |
| 工厂普工 | 按时薪计薪，固定排班 | 记录加班时长，查看月收入 |
| 临时工/散工 | 零散工作，偶尔记工 | 快速记录，无需登录即可使用 |

### 1.3 核心价值

- **无需登录即可使用** — 设备级匿名标识，离线记录不丢失
- **三种计薪模式** — 时薪（按时长）、日薪（按天数）、计件（按数量）
- **自动计算工钱** — 输入时长/天数/件数，自动乘以费率，精确到分
- **一键对账** — 预估工钱 vs 实发工钱差额一目了然

### 1.4 平台覆盖

| 平台 | 条件编译 | 备注 |
|------|----------|------|
| 微信小程序 | `MP-WEIXIN` | 主平台，静默登录 |
| App (Android/iOS) | `APP-PLUS` | 一键登录支持 |
| H5 | `H5` | 浏览器访问 |

## 二、用户角色

### 2.1 匿名用户（未登录）

- 使用设备 UUID 作为身份标识
- 全部本地功能可用（记工、统计、对账、项目管理）
- 数据仅存储在本地，不同步到云端
- 登录后自动将匿名数据合并到用户账户

### 2.2 登录用户

- 通过微信授权（小程序）或一键登录（App）完成认证
- 所有本地数据自动同步到云端
- 支持多设备数据合并（以最后修改时间为准）
- 可进行数据备份和恢复

### 2.3 权限边界

| 功能 | 匿名用户 | 登录用户 |

| 记工 CRUD | ✅ | ✅ |

## 五、数据流向

### 5.1 三层架构

```
┌─────────────────────────────────────────────────────┐
│  Layer 1: 计算引擎 (calculator.js)                    │
│  calcPay / calcNetPay / calcDuration / round2        │
│  所有金额计算收敛于此，不依赖 UI 和 Store              │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│  Layer 2: 状态管理 (Pinia Stores)                     │
│  workStore / projectStore / salaryStore /            │
│  holidayStore / userStore                            │
│  封装本地存储读写 + 云端同步逻辑                       │
└──────────────────────┬──────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────┐
│  Layer 3: 页面 (Pages)                                │
│  11 个页面，通过 computed 读取 Store，                │
│  通过 methods 调用 Store actions                      │
└─────────────────────────────────────────────────────┘
```

### 5.2 本地优先策略

```
用户操作 → Store Action → 1. col.add/update/remove (本地存储立即生效)
                        → 2. this.records 响应式更新 (UI 即时刷新)
                        → 3. enqueueSync (2 秒防抖入队)
                        → 4. flushSyncQueue → callWork('sync') (后台同步)
```

### 5.3 云端拉取合并策略

```
loadRecords/loadProjects 被调用时:
  1. 从本地加载 (瞬间完成，不阻塞 UI)
  2. 如果已登录 → pullFromCloud (后台异步)
    2a. 逐条比对 _id:
        - 本地有 && 本地更新时间 > 云端 → 推送本地到云端
        - 云端新 || 云端更新时间 >= 本地 → 云端覆盖本地 (upsert)
  3. 重新加载到 Pinia state
```

### 5.4 离线兼容

- 无网络或云函数不可用时，`syncStatus` 设为 `'error'`/`'offline'`
- 同步队列保留在内存中（`_syncQueue`），下次 flush 时重试
- 所有用户操作完全基于本地数据，云端同步为后台增强

## 七、业务规则

### 7.1 三薪制计算规则

#### 时薪模式 (hourly)

```
pay = round2(duration × rate)
net_pay = round2(pay + subsidies − deduction)

rate 优先级链:
  record.rate > getRateByType(dayType, project, salaryConfig) > 0

getRateByType 逻辑:
  1. project[dayType + '_rate'] > 0 → 使用项目费率
  2. salaryConfig[dayType + '_rate'] > 0 → 使用全局费率
  3. 否则 → 0（触发零费率提示）
```

#### 日薪模式 (daily)

```
pay = round2(days × daily_rate)
net_pay = round2(pay + subsidies − deduction)

daily_rate 优先级:
  record.daily_rate > project.daily_rate > salaryConfig.daily_rate > 0
```

#### 计件模式 (piece)

```
pay = round2(quantity × piece_rate)
net_pay = round2(pay + subsidies − deduction)

piece_rate 优先级:
  record.piece_rate > project.piece_rate > salaryConfig.piece_rate > 0
```

### 7.2 精度策略

| 精度 | 规则 | 示例 |
|------|------|------|
| 15 分钟 | `Math.ceil(hours × 4) / 4` | 1h10m → 1h15m |
| 30 分钟 | `Math.ceil(hours × 2) / 2` | 1h10m → 1h30m |
| 1 小时 | `Math.ceil(hours)` | 1h10m → 2h |
| 精确 | `Math.round(hours × 100) / 100` | 1h10m → 1.17h |

金额精度：统一 `round2(n) = Math.round(n × 100) / 100`

### 7.3 节假日判定规则

```
输入: dateStr (YYYY-MM-DD)

判定优先级:
  1. holidays 字典命中 → 'holiday'
  2. makeupDays 字典命中 → 'weekday' (调休上班日)
  3. new Date(dateStr).getDay() === 0 || 6 → 'weekend'
  4. 其他 → 'weekday'
```

数据来源优先级：云端拉取（云函数 `holiday-data`）→ 本地缓存（`holiday_data`）→ 静态硬编码 2026 年数据

### 7.4 结算逻辑

- 每条记录有 `settled: boolean` 字段
- 首页可筛选已结算/未结算
- 对账页按项目批量切换结算状态
- 未结算合计 = 汇总所有 `!settled` 记录的 `net_pay || pay`

### 7.5 时段重叠检测（仅时薪模式）

云函数 `addRecord` 检测条件：
```
同一天 + 同用户 + start_time < 新记录的 end_time + end_time > 新记录的 start_time
```
命中 → 返回 `{ duplicated: true }`，不创建重复记录

## 八、边界场景

### 8.1 零费率场景

| 场景 | 处理 |
|------|------|
| 时薪模式 + 项目和全局都无费率 | 底部弹出费率设置面板（快捷设置） |
| 日薪模式 + 项目和全局都无费率 | Toast "该项目未设置日薪金额" |
| 计件模式 + 项目和全局都无费率 | Toast "该项目未设置计件单价" |

### 8.2 空状态场景

| 页面 | 空状态 UI |
|------|-----------|
| 首页 | 日历图标 + "还没有记工记录" + "点击下方 + 开始记录" |
| 统计页 | 图表图标 + "本月没有记工记录" |
| 对账页 | 对账图标 + "本月没有记工记录" |
| 项目列表 | 房屋图标 + "还没有项目" |

### 8.3 跨日记工

`date.js` 的 `calcDuration` 支持跨日场景：
```
startTime = '22:00', endTime = '02:00'
diff = 2*60 − 22*60 = −1200 分钟
diff < 0 → diff += 24*60 → +240 分钟 = 4 小时
```

### 8.4 超长时长

- 时长滑块最大 24 小时（`DURATION_SLIDER.max = 24`）
- 无硬性上限校验，由用户自由输入

### 8.5 离线使用

- 无网络时所有功能正常工作
- `syncStatus` 显示 `'offline'`
- 登录后再联网自动合并

### 8.6 数据量级

- 本地存储无数量限制（取决于设备容量）
- 云端单次拉取上限 1000 条（`limit(1000)`）
- 批量导入每批最多 50 条

## 九、异常处理

### 9.1 网络异常

| 场景 | 处理 | 用户感知 |
|------|------|----------|
| 云函数调用失败 | 同步队列保留，`syncStatus = 'error'` | 静默（数据在本地安全） |
| 静默登录超时 | 3 秒 race 超时，不影响使用 | 静默（以匿名用户继续） |
| 云端拉取失败 | catch 块为空，本地数据保持不变 | 静默 |

### 9.2 认证异常

| 场景 | 处理 |
|------|------|
| Token 过期 | `hasToken()` 返回 false，`syncStatus = 'offline'` |
| JWT 验证失败（401） | `callWork` 抛出 `Error('NOT_AUTH')` |
| 未登录调用需认证接口 | 云函数返回 `{ code: 401, message: '请先登录' }` |

### 9.3 数据冲突

| 场景 | 策略 |
|------|------|
| 本地和云端同一条记录都有修改 | 最后修改时间（LWW）：`localTime > cloudTime` → 推送本地；否则 → 云端覆盖本地 |
| 时薪模式时段重叠 | 云函数返回 `{ duplicated: true }`，前端 toast "该时段已有记录" |
| 批量同步冲突 | 云函数返回 `conflicts` 数组，记录被跳过 |

### 9.4 输入校验

| 校验项 | 规则 | 错误提示 |
|--------|------|----------|
| 时薪模式时长 | `duration > 0` | "请设置起止时间" |
| 时薪模式日期类型 | `['weekday','weekend','holiday'].includes(day_type)` | "日期类型无效" |
| 日薪模式天数 | `days >= 1` | "日薪模式必须填写天数" |
| 日薪模式费率 | `daily_rate > 0` | "该项目未设置日薪金额" |
| 计件模式数量 | `quantity >= 0` | "计件模式必须填写数量" |
| 计件模式单价 | `piece_rate > 0` | "该项目未设置计件单价" |

### 9.5 降级策略

| 功能 | 正常路径 | 降级路径 |
|------|----------|----------|
| CSV 导出（小程序） | 写入文件 → 分享 | 复制到剪贴板 |
| 节假日数据 | 云端拉取 | 本地缓存 → 静态数据 |
| 云端同步 | `callWork('sync')` | 本地保存，等下次联网 |
| 长图生成 | Canvas 绘制 → 转图片 | Toast "生成失败，请重试" |

## 十、非功能需求

### 10.1 性能

| 指标 | 目标 | 实现方案 |
|------|------|----------|
| 首屏加载 | < 1s（本地数据 < 500 条） | `preloadLocalData` 同步加载，不阻塞 UI |
| 云端同步 | 2 秒防抖，批量提交 | `_syncTimer` + `flushSyncQueue` |

| 图表渲染 | < 500ms | uCharts Canvas，400ms 延迟渲染 |

| 措施 | 实现 |
|------|------|
| 身份认证 | JWT HMAC-SHA256，Secret 需在生产环境更换 |
| 数据隔离 | 云函数通过 `user_id` / `device_id` 过滤查询和更新 |
| 传输安全 | uniCloud 自动 HTTPS |
| 密码安全 | 依赖 uni-id 的密码哈希存储 |
| XSS 防护 | Vue 模板默认转义 + CSV 导出替换逗号为分号 |

### 10.3 兼容性
